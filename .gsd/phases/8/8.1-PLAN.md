# Plan 8.1: Redis Infrastructure — Shared Client & Pair Locks

## Objective
Extract the hard-coded `new IORedis()` into a shared client module and implement the pair-lock
primitives (acquire + Lua-guarded release). This foundation is required by the dispatcher and the
cooldown/seen modules in later plans.

## Context
- `.gsd/phases/8/RESEARCH.md` — Architecture decisions and Redis key schemas
- `examples/social-server/src/worker/bullmq.ts` — Current inline `new IORedis()` to be replaced
- `examples/social-server/package.json` — ioredis ^5.x already installed

<task type="auto">
  <name>Implement pair-lock helpers</name>
  <files>
    examples/social-server/src/redis/locks.ts
  </files>
  <action>
    Create `src/redis/locks.ts` with two exported async functions: `acquireLock` and `releaseLock`.

    Key schema: `lock:{contestId}:pair:{pairKey}` (e.g., `lock:contest-1:pair:a::b`)

    `acquireLock(contestId: string, pairKey: string, ownerId: string): Promise<boolean>`
    - Calls `redis.set(key, ownerId, 'NX', 'PX', 60000)`
    - Returns `true` if lock acquired (result === 'OK'), `false` otherwise
    - Import `redis` from `./client`

    `releaseLock(contestId: string, pairKey: string, ownerId: string): Promise<void>`
    - Runs the following Lua script via `redis.eval(script, 1, key, ownerId)`:
      ```lua
      if redis.call("GET", KEYS[1]) == ARGV[1] then
        return redis.call("DEL", KEYS[1])
      else
        return 0
      end
      ```
    - Only deletes the key if the stored value matches `ownerId` (safe release)
    - Returns void; ignore the numeric result

    Do NOT implement retry logic here — retry is the dispatcher's responsibility.
  </action>
  <verify>grep -n "acquireLock\|releaseLock\|eval" examples/social-server/src/redis/locks.ts</verify>
  <done>
    - `src/redis/locks.ts` exports `acquireLock` and `releaseLock`
    - Lua script used for safe release
    - Lock key format uses `lock:{contestId}:pair:{pairKey}`
  </done>
</task>
