# Plan 1.3: Selection & Confidence strategies

## Objective
Implement the "Brain" of the engine: deciding which pair to show next (Selection) and estimating the reliability of the current ranking (Confidence).

## Context
- src/engine/index.ts
- src/model/gaussian.ts
- .gsd/SPEC.md (Goals: Smart Defaults, Confidence)

## Tasks

<task type="auto">
  <name>Implement Selector Module</name>
  <files>src/selector/index.ts, src/types.ts</files>
  <action>
    Implement `nextPair` logic. Strategy: "Boundary Band" (or "Utility" based).
    - Identify a set of "active" items (using a sliding window or band around a target rank if sorting, or just high-uncertainty items).
    - For Phase 1 v0.1: Simple "Quality Match" strategy.
        1. Pick `Item A` (Randomly or one with fewer matches).
        2. Pick `Item B` that has close `mu` to A (maximizes draw probability / information gain).
    - Return `[ItemA, ItemB]`.
  </action>
  <verify>npx tsc --noEmit</verify>
  <done>Selector returns a specific pair, not just random ones.</done>
</task>

<task type="auto">
  <name>Implement Confidence Module (Monte Carlo)</name>
  <files>src/confidence/index.ts, test/confidence/montecarlo.test.ts</files>
  <action>
    Implement `computeStability(items: Item[])`.
    - Approach: Monte Carlo sampling.
    - Loop N times:
        1. Sample performance for each item `P_i ~ N(mu_i, sigma_i)`.
        2. Sort items by `P_i`.
        3. Store rank.
    - Calculate:
        - `Kendall's tau` (vs current mean order) OR
        - `Top-K intersection` (how often is the top K stable?).
    - Return a stability score (0.0 - 1.0).
  </action>
  <verify>npx vitest run montecarlo</verify>
  <done>Confidence metric returns low score for fresh items, high score for separated items.</done>
</task>

## Success Criteria
- [ ] `nextPair()` returns meaningful comparisons (high uncertainty pairs).
- [ ] `computeStability()` provides a 0-1 confidence metric.
- [ ] Both modules integrated into `TasteEngine`.
