# Plan 7.2: Setup BullMQ for Event Persistence & Snapshotting

## Objective
Implement asynchronous background processing using BullMQ within the `examples/social-server` package to persist vote events and snapshot active engine states.
- **Why**: Phase 7 requires "Instant Next Pair response". Database writes must not block the API thread. A BullMQ worker decouples the fast in-memory update from the slower persistence layer (Redis/Database), fulfilling the `BullMQ setup for snapshotting and event log persistence` requirement in `ROADMAP.md`.
