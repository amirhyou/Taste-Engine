# Plan 8.3: RedisDispatcher & Route Wiring

Assemble all guardrail modules into a `RedisDispatcher` wrapper class and wire it into the HTTP
routes, replacing the direct `ContestCoordinator` calls. Also fix the Phase 7 `zValidator` bug and
make `userId` required. This plan depends on Plans 8.1 and 8.2.

    **2. `src/dispatch/RedisDispatcher.ts`**
    Wrapper class that delegates to `ContestCoordinator` after running Redis guards.

    Constructor: `constructor(private coordinator: ContestCoordinator) {}`

    Method: `async getNextPair(contestId: string, userId: string): Promise<PairRecommendation | null>`
    ```
    1. if (await isOnCooldown(userId)) throw a 429-flagged error
    2. Loop up to 5 times:
         a. call this.coordinator.getNextPair(contestId) → pair
         b. if pair is null/undefined break (exhausted)
         c. pk = pairKey(pair.a, pair.b)
         d. if !(await hasSeen(userId, contestId, pk)) break  ← found fresh pair
    3. if pair exists: await markSeen(userId, contestId, pairKey(pair.a, pair.b))
    4. return pair
    ```

    Method: `async submitVote(contestId: string, userId: string, vote: VotePayload): Promise<PairRecommendation | null>`
    Where `VotePayload = { pair: [string, string]; choice: number }` (no userId — already separate)
    ```
    1. if (await isOnCooldown(userId)) throw a 429-flagged error
    2. const pk = pairKey(vote.pair[0], vote.pair[1])
    3. const ownerId = crypto.randomUUID()
    4. const locked = await acquireLock(contestId, pk, ownerId) with 3 retries, 50ms apart
       - if still not locked after retries: throw a 409-flagged error
    5. let next: PairRecommendation | null
    6. try:
         next = this.coordinator.submitVote(contestId, { ...vote, userId })
    7. finally:
         await releaseLock(contestId, pk, ownerId)  ← always release, even on error
    8. await recordVote(userId)
    9. if next: await markSeen(userId, contestId, pairKey(next.a, next.b))
    10. return next
    ```

    Error convention — throw plain `Error` objects with a `.status` property for the route to read:
    ```typescript
    class HttpError extends Error {
      constructor(public status: number, message: string) { super(message); }
    }
    ```
    Define `HttpError` in this file and use it for the 409 and 429 throws.

    Retry helper (inline, not exported):
    ```typescript
    async function withRetry<T>(fn: () => Promise<T>, attempts: number, delayMs: number): Promise<T> {
      for (let i = 0; i < attempts; i++) {
        const result = await fn();
        if (result) return result;
        if (i < attempts - 1) await new Promise(r => setTimeout(r, delayMs));
      }
      return fn(); // last attempt, let it throw if needed
    }
    ```
    Use this for the lock-acquire retry (attempts=3, delayMs=50).
