# Plan 8.2: Guardrail Helpers — Cooldowns & Seen Sets

## Objective
Implement the two per-user guardrail modules: shadow-ban cooldowns (rate counter + TTL key) and
seen-pair sets (sorted set with size cap). These are pure Redis utilities consumed by the dispatcher
in Plan 8.3 and have no dependency on Plan 8.1's lock helpers (only on the shared Redis client).

## Context
- `.gsd/phases/8/RESEARCH.md` — Key schemas, thresholds, and retention caps
- `examples/social-server/src/redis/client.ts` — Must exist (created in Plan 8.1)

    Create `src/redis/cooldown.ts` with three exported async functions.

    Key schemas:
    - Rate counter: `rate:{userId}:votes` — rolling 10s window counter
    - Cooldown flag: `cooldown:{userId}` — presence = user is banned for 5 mins

    `isOnCooldown(userId: string): Promise<boolean>`
    - `return (await redis.exists(`cooldown:${userId}`)) === 1`

    `recordVote(userId: string): Promise<void>`
    - Atomically increment and set expiry using a pipeline:
      ```typescript
      const key = `rate:${userId}:votes`;
      const count = await redis.incr(key);
      if (count === 1) {
        await redis.expire(key, 10); // set 10s TTL on first increment only
      }
      if (count > 30) {
        await triggerCooldown(userId);
      }
      ```
    - Threshold: >30 votes in 10s triggers cooldown

    `triggerCooldown(userId: string): Promise<void>`
    - `await redis.set(`cooldown:${userId}`, '1', 'EX', 300)` (5 min = 300s)

    Import `redis` from `./client`. No other dependencies.

  <action>
    Create `src/redis/seen.ts` with three exported async functions.

    Key schema: `seen:{contestId}:{userId}` — Redis sorted set (score = timestamp ms)
    Member format: the normalized pairKey string (e.g., `"a::b"`)
    Cap: 5,000 members per user per contest

    `hasSeen(userId: string, contestId: string, pk: string): Promise<boolean>`
    - `return (await redis.zscore(`seen:${contestId}:${userId}`, pk)) !== null`

    `markSeen(userId: string, contestId: string, pk: string): Promise<void>`
    - Add to sorted set with current timestamp as score:
      `await redis.zadd(`seen:${contestId}:${userId}`, Date.now(), pk)`
    - Then trim to cap (keep newest 5000):
      `await redis.zremrangebyrank(`seen:${contestId}:${userId}`, 0, -(5000 + 1))`
    - Trimming after every add is fine — ZREMRANGEBYRANK is O(log n + removed)

    Do NOT set a TTL on the key itself — the cap alone bounds memory.
    Do NOT accept a `PairRecommendation` object — only accept the raw `pk: string` to keep
    this module independent of core types.
  </action>
  <verify>grep -n "hasSeen\|markSeen\|zremrangebyrank" examples/social-server/src/redis/seen.ts</verify>
  <done>
    - `src/redis/seen.ts` exports `hasSeen` and `markSeen`
    - Sorted set with `Date.now()` score
    - Trimmed to 5,000 members after each write
    - No TTL on key
  </done>
