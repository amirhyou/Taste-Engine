## Overview

Taste Engine is a **TypeScript monorepo** for high-precision identification of Top-K items from noisy, pairwise human preferences. The system uses a TrueSkill-inspired Bayesian model with active learning to intelligently select pairs and estimate confidence thresholds for when ranking has converged.

## Components

### Core Engine (`packages/core`)

**Purpose:** Pure algorithmic library implementing TrueSkill-based ranking system

**Key Modules:**
- **Engine** (`engine/engine.ts`) — Orchestrates voting, pair selection, status queries
- **Online Model** (`model/onlineModel.ts`) — Bayesian item state tracking
- **Pair Selector** (`selector/selector.ts`) — Active learning with information gain scoring
- **Stopping Criterion** (`stopping/stopping.ts`) — Monte Carlo-based convergence detection
- **Confidence Estimator** (`confidence/confidence.ts`) — Win probability calculation
- **Utils** (`utils/`) — Decay, statistics, random sampling, graph cycles

**Dependencies:** Zero external dependencies (pure TS)

### Adapters Package (`packages/adapters`)

**Purpose:** Framework-specific integration helpers (currently minimal)

### Mobile App (`examples/mobile-app`)

**Framework:** React Native (Expo 54) + Expo Router

**Key Subsystems:**
- **Screens** (`src/screens/`) — ContestHub, VotingScreen, ResultScreen, etc.
- **Services** (`src/services/`) — Spotify auth/API, engine lifecycle, session control, storage
- **Hooks** (`src/hooks/`) — useEngineStatus, useContestVoting, useSpotifyUser
- **UI Components** (`src/components/`) — PairStack, StrengthSlider, Button, etc.

**Data Flow:**
Spotify OAuth → Load playlists → Initialize Engine → Voting loop (nextPair → ingest → status) → Results

### React Web (`examples/react-web`)

**Framework:** React 19 + Vite

**Use Case:** Browser-based demo with form voting, real-time leaderboard

### Node CLI (`examples/node-cli`)

**Use Case:** Terminal REPL for offline testing, batch processing

### Social Server (`examples/social-server`)

**Framework:** Hono + Node.js

**Architecture:**
- HTTP API (Hono routes) → ContestCoordinator → Redis store + BullMQ queue → VotePersister worker
- Manages per-contest Engine instances, vote dispatch, rate limiting, moderation

**Key Services:**
- **Redis** — Contest metadata, engine snapshots, pair counts, user cooldowns
- **BullMQ** — Async vote processing queue
- **RedisDispatcher** — Message broker for vote events

## Data Flow

**Single-User (Mobile):**
1. User auth + playlist load → Engine init → nextPair() → vote → ingest() → status check → continue or show results

**Multi-User (Server):**
1. Contest created → Multiple clients POST votes → Server validates + enqueues → Worker processes + updates snapshot → Clients poll status
